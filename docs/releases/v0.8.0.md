# TobiiLinux v0.8.0 — smoothing, response curves and a recentre key

Most of this release is a contribution: [PR #3] by [hanusspi] adds adaptive
smoothing, a response curve for every output axis, an output speed limit,
auto-centre, a Tuning window to shape all of it by hand, and `tobii recentre`
so a keyboard shortcut can recentre the view. The rest is what reviewing that
work turned up, in it and in the hub around it.

**Some defaults changed for everyone.** If head tracking feels different after
updating, read the next section first. Where there is a way back to the old
behaviour, each change says how.

Nothing in the driver, the protocol or the USB layer changed.

  Unofficial. Not affiliated with, endorsed by, or supported by Tobii.
  Use at your own risk.

[PR #3]: https://github.com/Tropaion/Tobii_Linux/pull/3
[hanusspi]: https://github.com/hanusspi


## Changed without you touching anything

These apply to every output: opentrack, the Wine bridge, the virtual joystick
and plain `tobii headpose`.

- **x is mirrored.** A lean to the right now moves the in-game head to the
  right. If x comes out backwards in your game, or your opentrack profile
  already mirrors it (you would now get a double flip):

  ```sh
  tobii games set head_x_invert false
  ```

- **Smoothing is adaptive.** A One-Euro filter replaces the fixed one. It
  smooths hard while your head is still and opens up as you move. Your
  `games.toml` has a `filter_alpha` and no `filter_mode`, so **a tuned alpha
  is now ignored**. To get the old filter and your alpha back:

  ```sh
  tobii games set filter_mode ema
  ```

- **Output has a speed limit**, 240°/s for rotation and 400 mm/s for movement,
  so a sudden jump in the measurement arrives in game as a fast sweep rather
  than a cut. It applies after the response curves, so a curve with a lot of
  gain reaches it on slower head movements. To effectively switch it off:

  ```sh
  tobii games set filter_max_rot_speed_deg_s 100000
  tobii games set filter_max_move_speed_mm_s 100000
  ```

- **A recentre levels pitch too.** v0.4.0 left pitch alone on purpose. Now
  **Recentre view**, `tobii headpose --recenter` and the new `tobii recentre`
  take pitch along with yaw and roll. The zero from
  `tobii headpose --calibrate-pitch` stays underneath, as the correction for
  how the tracker is mounted. A recentre also re-takes the neutral position.
  With Extended View on, where you were looking also becomes the centre, but
  only if that was near the middle of the screen. A head that nods during the
  measuring second is refused, the same as one that turns. There is no setting
  for the old behaviour.

- **The hub is taller.** The readout has a JOYSTICK OUTPUT block, and the
  *Head tracking for games* card has two new rows: auto-centre and the
  recentre key.


## New

### Response curves

Every output axis (`yaw`, `pitch`, `roll` in degrees; `x`, `y`, `z` in mm) has
a curve, applied after smoothing and before any game sees the pose:

```sh
tobii games set head_yaw_deadzone 1.5      # ignore the first 1.5° around centre
tobii games set head_yaw_input_max 30      # 30° of head turn ...
tobii games set head_yaw_output_max 90     # ... gives 90° in game
tobii games set head_yaw_curve power:1.6   # gentle near centre, steeper toward the edge
tobii games set head_yaw_invert true       # mirror the axis
```

The defaults pass every axis through unchanged, except x.

### The Tuning window

**Tuning…** on the games card opens a window that draws each curve and lets you
drag it. While game output is on, it also shows where your head sits on each
curve right now. It holds the smoothing settings too. Three things to know:

- **It saves a moment after you change something** (300 ms), when it loses
  focus, and when it closes, rather than on every step of a slider.
- **It keeps the tracker on while it is open**, so with game output on the
  live marker has something to show.
- **It follows the file.** A change made on the hub or with `tobii games set`
  shows in the window straight away.

Values set from a terminal show as they are rather than clamped to a slider's
range, and every slider's tooltip is in the help window (F1) under
*Tuning window*.

### A key for recentring

`tobii recentre` (or `tobii recenter`) asks the running hub to recentre, exactly
as its button does. Bind it to a keyboard shortcut in your desktop's settings.
That works under Wayland, where a program cannot grab a global hotkey.

- **On COSMIC**, the *Recentre key* button writes the shortcut itself, and
  shows the key. Press it to choose a new one, or Backspace to remove it. It
  updates when the key is changed in COSMIC Settings.
- **Elsewhere**, the button is **Copy**: it puts the exact command on the
  clipboard, ready to paste into your desktop's shortcut settings.

A per-user `tobii uninstall` takes that shortcut back out of COSMIC's file when
the `tobii` it runs is being removed, and leaves your own shortcuts alone.
`sudo tobii uninstall --system` does not touch your COSMIC file, so after
removing a system install, remove the key in COSMIC Settings.

### Auto-centre (off by default)

The checkbox on the games card, or `tobii games set auto_centre true`. While you
look near the middle of the screen with your head within 12° of straight, it
slowly pulls "straight ahead" toward how you are actually sitting. It leaves
pitch alone. It is off by default because it changes what a manual recentre
means, and because it cannot tell sitting crooked from a small turn held while
looking at the middle of the screen, and draws that back too.


## Refused now

`tobii games set` and `tobii games profile apply` refuse two settings that
would make a curve jump:

- a deadzone at or past that axis's `input_max`;
- a curve exponent outside 0.1 to 10.

Past either limit, a movement out of the deadzone jumps straight to full output
(or, far above ten, an axis hardly moves at all). The message says what is
wrong and, for `games set`, in which order to change the two keys. **A file
that already says otherwise still loads exactly as before.** Only a new problem
is refused.


## Fixed

In the contributed work, before it shipped:

- **The view could end up permanently tilted:**
  - A nod during the measuring second became "level", and the head read as
    tilted for the rest of the session.
  - A recentre taken before the pitch zero was set, followed by setting it,
    sent a level head out about 22° off until the next recentre.
- **Pitch jumped while the head model dropped out.** After a recentre, while
  the model briefly had no answer, pitch went out offset by the recentre's
  pitch. A recentre whose measuring second spanned the model dropping out or
  coming back was refused as "head moved".
- **Writing the shortcut could break COSMIC's file.** A hand-written comment
  in COSMIC's shortcut file could lead to an unreadable file, or to one of your
  own shortcuts being deleted.
- **A key that types could be bound.** Keys like ö, ß or AltGr+Q could be bound
  on their own, which stops that key typing everywhere.

In the hub:

- **Windows outlived themselves.** The head-model dialogs leaked on every
  open, and several timers kept parts of the hub alive past quit. Dialogs now
  close when the hub quits.
- **The accuracy check lost its results on Alt+F4.** It now reports what it
  measured.
- **A pitch measurement that saved could go unused.** If it saved but saw your
  head move, the old zero stayed in use until the next connect. The card now
  always shows the zero actually in use.
- **Strength presets overwrote a setting.** With a sideways reach of 25, 45 or
  70, the games card's refresh replaced your vertical reach with that preset's.
  A strength radio can now show none selected, when your reach matches no
  preset.

In settings writes, from the hub and the CLI alike:

- **A symlinked settings file was replaced.** A settings file that is a symlink
  (a dotfiles setup, say) now stays one. One that cannot be written through,
  such as a Nix store link, is replaced as before.
- **Saving lost a file's permissions.** A settings file you made private stays
  private when it is saved.


## Measured, and not

**Measured:**

- **Unit tests** cover the curves, the filter, the speed limit, the
  recentre's refusals and the COSMIC file format, comments included.
- **Display tests** cover the Tuning window, the COSMIC key button and the
  head-model dialogs. They run by hand in a nested compositor, not in CI.

**Not measured:**

- **The new defaults in a game.** No game has been measured with the new
  filter constants and speed limits; they are the contribution's choices.
- **The gaze box.** How near the middle counts as "near the middle" for the
  Extended View centre is a guess (the middle 60% of the screen).
- **COSMIC.** This release was tested on KDE.

`docs/wiki/Quality-and-Risks.md` §11.3q has the full list.
